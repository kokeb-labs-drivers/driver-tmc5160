Stepper motor controller and driver

TMC5160 Driver¶

A C++20 driver for the TMC5160 and TMC5160A stepper motor controller and driver. It starts the chip safely, moves the motor in physical units, and refuses the register writes that can burn out a motor or a bridge, on any MCU, over SPI or UART.

Quickstart API guide Source on GitHub

The TMC5160A is a controller and driver for two-phase bipolar stepper motors: it runs the motion profile itself and drives an external MOSFET bridge for coil currents from 1 A to several 10 A (Title page, p. 1).

Quick start¶

Wire the chip as above, write the port (Porting), then declare the motor and move it:

#include "tmc5160.hpp"

int spin_one_revolution(MyPort& port) {
  // 1. Declare the motor and the board. The driver derives every current register from these two.
  const tmc5160::Config config =
      tmc5160::MakeConfig(tmc5160::Motor{.rated_rms_ma = 1000, .coil_resistance_mohm = 6000},
                          tmc5160::Board{.rsense_mohm = 100, .supply_mv = 24'000});
  tmc5160::TMC5160<MyPort> motor(port, config); // no I/O yet

  if (auto r = motor.EnsureInitialized();
      !r) {                           // 2. bus, strap, VERSION, every register, driver off
    return static_cast<int>(r.error); //    Bus, Timeout, DeviceIdMismatch, InvalidArgument ...
  }
  if (auto r = motor.Enable(); !r) { // 3. DRV_ENN active, TOFF written
    return static_cast<int>(r.error);
  }
  if (auto r = motor.MoveTo(51'200); !r) { // 4. one revolution at 256 microsteps, 200 full steps
    return static_cast<int>(r.error);
  }
  return 0; // poll PositionReached(); Disable() when done
}

From docs/hardware.yml; kokeb-docs hardware --check confirms that every API name is in inc/tmc5160.hpp, inc/tmc5160_types.hpp and every register in inc/tmc5160_registers.hpp.

The driver has no platform code. You give it a small class that brings the bus up and moves bytes; it does the rest: the start-up sequence, the datagram framing and CRC, the current arithmetic, the ramp registers, the guards and the timeouts. Nothing here has run on a chip yet: it is tested against an independent model of the TMC5160 (see Testing and CI).

  • One object per chip. TMC5160<YourPort> takes a reference to your port and does no I/O until EnsureInitialized(). See API guide.
  • A current that cannot exceed the motor. You declare the motor and the sense resistor; every register is derived from them. See Current and limits.
  • A guard for every dangerous write. What the driver refuses, and the explicit acknowledgement that lifts a guard for one call. See Guards and acknowledgements.
  • Errors you can act on. Every call returns Result<T> with an Error such as Bus, Timeout, Refused or UnexpectedReset. See API guide.
  • Both buses. SPI and UART ports, daisy chains and multi-node lines, STEP/DIR mode. See SPI protocol and UART protocol.
  • No heap, no exceptions, no RTTI. The host tests build with -fno-exceptions -fno-rtti. See Contract.
  • Where the datasheet is unclear, a decision. Fifty ambiguities are listed with the reading the driver takes. See Ambiguities.
