Coverage map¶

Every register, bit field, mode, pin, rating and coded range of the datasheet, and where the driver handles it.

The rows come from the design matrix this driver was built to: 593 rows, each with the datasheet section and printed page, the driver API that handles it and a status:

Status Meaning
OK The driver handles it and a host test covers it against the chip model
GUARD A dangerous value or sequence: the driver refuses it unless the call carries an acknowledgement (Guards)
INFO Documented only: a pin or rating with no driver function, a fact the application must respect
TODO Out of scope by the owner's decision (OTP programming); the driver never writes it

The tests are in tests/ and are named after the feature they check; nothing here has run on a chip. An OK row is backed by an assertion that fails when the handled behaviour changes (checked by the mutation run in Testing); the DcStep (DCCTRL), encoder (ENCMODE) and bridge (DRV_CONF) bit positions are asserted field by field in tests/test_mutants.cpp.
