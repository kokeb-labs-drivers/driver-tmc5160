Detailed Description

template<AnyPort Port>
class tmc5160::TMC5160< Port >

Driver for one TMC5160 on a platform port.

Lifecycle: construct with the configuration (no I/O), then EnsureInitialized(), the one way to start (bus up, strap and version check, GSTAT cleared, every register written from the configuration with the driver still off), use, Deinitialize(). Every call that touches the chip returns Error::NotInitialized until EnsureInitialized() has succeeded. After a chip reset (UnexpectedReset) the driver is uninitialised again: call EnsureInitialized().

Optional port hooks, found at compile time:

Hook Used for Without it
void DelayUs(uint32_t us) noexcept UART recovery, StealthChop tuning wait Compile error where a wait is needed
bool GpioSet(CtrlPin, GpioSignal) noexcept DRV_ENN, DcStep pins Enable() and Disable() use TOFF only; the pin must be tied low
bool GpioGet(InputPin, bool&) noexcept DIAG0, DIAG1, DcStep output levels Diag0Active() and Diag1Active() return Unsupported
uint32_t SckHz() const noexcept SPI clock check against the chip's limit No check
void Log(LogLevel, const char*) noexcept One line per lifecycle event or failure Nothing is logged
Template Parameters
PortYour class derived from SpiInterface<Port> or UartInterface<Port>.

◆ ClearFaults()

template<AnyPort Port>
Result< void > tmc5160::TMC5160< Port >::ClearFaults ( )
noexcept

Recover from a latched error once its cause is gone: disable (which stops the ramp generator), read DRV_STATUS, clear GSTAT, enable again when the driver was enabled.

A motor that is still turning when the call ends is not energised again: the faults are cleared, the driver stays disabled and the call returns Busy; call Enable() once the motor stands still.

Returns
Ok, NotInitialized, Busy (cleared, but not enabled again: the motor still turns), Refused (overtemperature or pre-warning still set, page 79), DeviceFault (the error returns at once), Bus or UnexpectedReset.

◆ Deinitialize()

template<AnyPort Port>
Result< void > tmc5160::TMC5160< Port >::Deinitialize ( )
noexcept

Switch the driver off (DRV_ENN inactive, TOFF 0) and mark the driver uninitialised.

Also ends the ramp (VSTART 0, VMAX 0, velocity mode) as Disable() does. The driver is uninitialised afterwards even if a write failed; a failed switch-off keeps the duty, so a later Deinitialize() or Stop() sends it again. On a driver that never sent anything (no EnsureInitialized() call, or the last switch-off completed) it does nothing and returns Ok; after a failed start-up it still switches the chip off.

Returns
Ok, Bus, Timeout, Crc (UART), VerifyFailed or UnexpectedReset.

◆ Enable()

template<AnyPort Port>
Result< void > tmc5160::TMC5160< Port >::Enable ( Verify  verify = Verify::None)
noexcept

Enable the driver: DRV_ENN active (when the port can), then TOFF from the configuration.

In the motion-controller mode the ramp generator must stand still first: the call returns Busy while RAMP_STAT.vzero is clear, a TZEROWAIT pause runs or, in position mode with VMAX not 0, position_reached is clear (one read, pages 44, 83 c: vzero alone is also set where the ramp turns back to a target it passed), so the bridge is never energised into a motion that began earlier. Call it again once the motor stands still. Ok does not mean the ramp is idle: a velocity-mode ramp held by a stop is left as it is. A stall stop is latched until ReleaseStall(); a reference switch stop holds only while the switch is active, and the motor restarts towards the target when the switch is released (pages 43, 44). A position move that a switch or a stall holds short of its target is Busy until Stop() or Hold() ends it.

Parameters
verifyExtra traffic to prove the CHOPCONF write.
Returns
Ok, NotInitialized, Busy (the motor is not at standstill), DeviceFault (an error is latched: ClearFaults()), Bus, VerifyFailed or UnexpectedReset.

◆ EnsureInitialized()

template<AnyPort Port>
Result< void > tmc5160::TMC5160< Port >::EnsureInitialized ( )
noexcept

Start the chip, once: the only way to initialise the driver.

Validates the configuration and the current plan, brings the bus up, quiesces the chip (TOFF 0, DRV_ENN inactive), checks IOIN (VERSION 0x30, SD_MODE strap equals Config::mode), clears GSTAT, then writes every register from the configuration; the driver stays disabled unless Config::begin_enabled. Each write is verified as Config::verify says. It sends the start-up traffic of docs/configuration.md and blocks only in port calls.

Returns
Ok, InvalidArgument, LimitExceeded, Refused (the configuration or the current plan fails a guard; no I/O), Unsupported (the port's SPI clock is too fast), Bus, Timeout, Crc (UART), DeviceIdMismatch, ModeMismatch, DeviceFault, VerifyFailed or UnexpectedReset; with Config::begin_enabled also Busy (the motor of the last session is still turning or in its TZEROWAIT pause: the start-up is undone with the bridge off, call it again once the motor stands still).

◆ RunVelocity()

template<AnyPort Port>
Result< void > tmc5160::TMC5160< Port >::RunVelocity ( int32_t  velocity,
Verify  verify = Verify::None 
)
noexcept

Run at a constant velocity until stopped.

Write order: in the same velocity mode VMAX, VSTART, mode; from the other velocity mode the mode, VSTART, VMAX (the new speed never reaches the move the other way, and a start from rest begins at VSTART); from position mode the mode, VMAX, VSTART with no read; from hold mode one VACTUAL read decides (at rest or running the asked way: VMAX first; else the mode first).

A position ramp in its TZEROWAIT pause, or turning back after an overshoot, can start its own run-back before the mode write arrives. The backward travel is at most VSTART*t + a*t^2/2 + (VSTART + a*t)^2/(2*AMAX) microsteps, with t the time from the call to the accepted mode write (one SPI datagram, or one 8-byte UART frame: 80 bit times, 8.3 ms at 9600 baud) and a = max(A1, AMAX) when V1 > 0 and VSTART < V1, else AMAX (V1 = 0 disables A1, page 40). Set TZEROWAIT longer than t when the application calls this during a position stop (page 83 c). From position mode the motor also keeps, or speeds towards, the old VMAX for that one write before the new VMAX applies. The bound counts from the call: a run-back that already moves keeps its speed for that write too, and 8.3 ms is the least t at 9600 baud (the port and the line add to it).

Parameters
velocityVelocity register units, signed (see units::VelocityRegFromHz()).
verifyExtra traffic to prove the writes.
Returns
Ok, NotInitialized, Unsupported, DeviceFault, Refused, LimitExceeded (above the declared maximum or 2^23 - 512), InvalidArgument (AMAX 0), Bus, VerifyFailed, UnexpectedReset.
